Case studies

Problem · approach · result
Humana · Senior BI Developer · 2025–present

Claims and membership reporting on Fabric, with Direct Lake

Problem

Financial, membership and claims reporting pulled from BigQuery, Databricks, Oracle and Azure SQL into large-scale models. Leadership needed fast, validated dashboards and quicker turnaround on ad hoc analysis.

Approach

  • Centralized upstream work in Fabric Data Pipelines and PySpark notebooks, with data quality checks before data reaches the model.
  • Implemented Direct Lake reporting over the Fabric Lakehouse.
  • Built reusable star-schema semantic models, then profiled slow measures in DAX Studio and restructured them.
  • Tuned indexing and partitioning, and added GPT natural-language summaries to executive dashboards.

Result

−60%execution time on the slowest DAX queries
−40%dashboard load time
<1squery response on large-scale reporting models
Humana · DevOps for BI

Source-controlled releases from Dev to Prod

Problem

Promoting reports between environments required manual data-source reconfiguration, which introduced release errors.

Approach

  • Saved reports and semantic models as PBIP/TMDL so every change is a readable diff in Git.
  • Routed changes through pull requests in Azure DevOps, with peer review of DAX, SQL and model design.
  • Set up parameterized Dev, Test and Prod stages in Power BI Deployment Pipelines, driven by Azure DevOps CI/CD.

Result

0manual data-source changes when promoting a release
Fewerrelease errors, with full version history for every model

Self-service analytics for a global brokerage

Problem

Senior finance and operations leaders across business units needed consistent revenue, cost and claims reporting. Recurring reports and data prep were largely manual, and BI-tool adoption stood at 45%.
